# BleachSan 1.2 research and release decisions

The main job is to recover space from identified caches while preserving application state and personal files. Research covered Windows cleanup controls, the browser and package-manager documentation, existing cleaner behavior, filesystem APIs, and the release pipeline. Five independent researchers reviewed these areas and non-authors checked the key source claims.

| Decision | Evidence and limits |
| --- | --- |
| Use a seven-day last-modified threshold inside the local user Temp root | Microsoft documents a one-week precedent. BleachSan applies it to files and preserves the directory and locks. [Disk Cleanup](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/cleanmgr) |
| Scope browser cleanup to verified cache leaves and recheck browser closure | Browser controls distinguish HTTP cache from logins, history, and persistent site data. Chromium’s Cache_Data is a subset of its complete HTTP cache. Firefox can override its profile cache location. [Chrome help](https://support.google.com/chrome/answer/2392709) · [Chromium source](https://chromium.googlesource.com/chromium/src/+/HEAD/content/browser/network_service_instance_impl.h) · [Firefox profile directories](https://firefox-source-docs.mozilla.org/toolkit/profile/index.html#profile-directories) |
| Expose filename-based discoveries for inspection | Next.js uses .next for deployable server and static output as well as cache data. Comparing another cleaner’s pattern list cannot establish that a file belongs in default cleanup. [Next.js build output](https://nextjs.org/docs/13/app/building-your-application/deploying#nextjs-build-api) · [Krokiet instructions](https://github.com/qarmin/czkawka/blob/master/instructions/Instruction_Krokiet.md) |
| Delegate Windows servicing to Windows tools | Microsoft documents dedicated servicing for WinSxS and the need to preserve Installer cache. The Windows Update download tree is outside the active cleaner. [WinSxS cleanup](https://learn.microsoft.com/windows-hardware/manufacture/desktop/clean-up-the-winsxs-folder) · [Windows Installer cache](https://learn.microsoft.com/en-us/troubleshoot/windows-client/application-management/missing-windows-installer-cache) |
| Reuse directory enumeration metadata and delete only through checked handles | Windows Rust DirEntry metadata reuses its listing response. The cleanup obtains directory handles without delete sharing and validates the file on the handle used for disposition. These limits can reduce coverage on inaccessible directories. [Rust DirEntry](https://doc.rust-lang.org/std/fs/struct.DirEntry.html#method.metadata) · [Windows file disposition](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle) |
| Keep estimates and free-space change distinct | Hard links and NTFS compression can make logical bytes differ from allocation. The displayed quantities are logical. [NTFS hard links](https://learn.microsoft.com/en-us/windows/win32/fileio/hard-links-and-junctions) |
| Ship a side-by-side GUI executable | The previous build requested elevation up front and forced running copies to stop during a build. The 1.2 manifest uses asInvoker. A versioned asset and its SHA-256 identify the build for download. [Windows manifests](https://learn.microsoft.com/en-us/windows/win32/sbscs/application-manifests) · [GitHub release assets](https://docs.github.com/en/rest/releases/assets) |

The workstation audit helped prioritize additional Chromium profiles, old NVIDIA shader caches, Electron archives, and Unreal Derived Data Cache. The rule files use app-relative locations. Personal paths and drive inventory data are outside the release.
